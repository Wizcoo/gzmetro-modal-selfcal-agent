# V54-Astra 双文件源码与 11/13–15 初始状态

本包对应此前逐点图册及解算 CSV 的 `current_fade07` 算法，并将 23:00–07:00 的 X 发布选择内置到 `Process()`。设备端仅需编译 `ModalSelfCal.cpp` 和 `ModalSelfCal.h`，依赖标准 C++17，无额外算法头文件、第三方数学库或新增运维参数。

## 状态是否必需

算法需要历史统计建立模态，**外部状态文件不是强制依赖**。无包时可 `Init(..., true)` 在线冷启动，按原规则收集本夜基准及学习数据；有足够数据时最早在首夜学习完成后进入冷启动修正。冷启动效果不能等同于已经具备三夜历史。

本次附左右线各六台、共十二台设备的初始状态，每台一份 `.state` 和同字节的 `.state.bak`。两轴历史均为 **2026-11-13、11-14、11-15**，每夜学习区间为 **22:00至次日02:00**，各240帧。13/14/15表示历史夜号，不是把历史学习改成23–07。

状态截止：左线2026-11-16 07:59:30.430，右线2026-11-16 07:59:50.107（北京时间）。用于11月16夜及之后接续处理；不用于回推11月13–15夜的独立验证。它们是此前连续因果原生回放的最终快照，保留原字节，未手改统计或配置。

有效率例外：右线780639346578的YD3104三夜有效233/720帧（32.36%），YD3405为0/720；不因状态包整体有三夜就把这两点标为可正常建模。它们仍遵守原核心有效率门限与透传规则，未补值或换历史夜。其余522点三夜池化有效率至少80%。

快照的历史队列已更新到13/14/15；快照内当前缓存仍属于15夜。下一夜正常收集22–23基准，在23点冻结时用保留的三夜历史建立新模态，不要理解成包中所有当前缓存都已经预先切换到16夜。

运行后历史会自动滚动，**不需要每天人工换初始包**。客户端仍应按现有流程保存运行状态，重启优先恢复最新运行状态；不要每次启动覆盖为本次初始状态。

## 建议使用对象接口

1. 每台设备独立一个 `ModalSelfCalState`。使用本版默认配置，勿沿用其他版本的显式参数覆盖。
2. 从该设备 `.markers.txt` 按行读取点名，保留准确顺序，调用 `Init(device_id, names, &error, false)`。
3. 二进制读取对应 `.state`，在任何 `Process()` 调用前导入；失败时检查错误，不当作导入成功继续运行。
4. 只接续 `resume.last_timestamp_ms` 之后的真实帧，按采集时间升序输入。缺少的历史可通过 `history_replay=true` 接续，回放结果不可发布。
5. 当夜22–23基准窗必须正常输入，且不能只在23–07调用核心。时间戳为Unix毫秒；内部默认北京时间UTC+8。

```cpp
#include "ModalSelfCal.h"

// device_id / names / bytes 均由本设备的配置和状态文件读取。
ModalSelfCalState engine;  // 本版默认即图册对应配置
std::string error;
if (!engine.Init(device_id, names, &error, false)) return; // 记录error并停止初始化
ModalSelfCalResumeInfo resume;
if (!engine.ImportState(bytes, &resume, &error)) return; // 记录error并停止初始化

// 每个真实新帧：raw_x/raw_y 必须按 names 同序；ROI无效/缺测填quiet_NaN。
ModalSelfCalResult result;
if (!engine.Process(timestamp_ms, raw_x, raw_y, &result, &error)) {
    // 本帧失败，不发布；沿用业务故障处理。
    return;
}
if (!result.output_ready) return; // 重复帧、旧帧、历史回放不发布
// 原始x/y继续保存不变。
// 数据库 calX = result.x，calY = result.y；按点名映射回数据库原记录顺序。
// result.x_source 表示X来自夜间链路还是原始观测。
```

上面是接入片段，错误分支必须在实际代码中终止该次初始化。同一帧只调用一次 `Process()`。输入应使用数据库原始x/y（pixel），不能把旧calX/calY再次输入；不要在算法中混入scale换算。状态名单顺序与数据库记录顺序是不同概念，需要按点名映射。

`Init(..., true)` 只用于明确选择冷启动时；不要吞掉导入错误并悄悄切到新流。任何修改设备号、点名单顺序或数学配置，都要重新评估状态兼容性，不能修改文件里的指纹强行导入。旧V54及不兼容的早期Astra状态不能直接替换本包。

## 输出约定

|本地采集时间|返回X|返回Y|
|---|---|---|
|23:00（含）至次日07:00（不含）|图册对应的新算法X|原算法核心Y|
|其他时间|同帧原始X|原算法核心Y|

所有帧仍经过原学习、滤波和缓存更新，再选择返回X；不会因07点切回原始值而停止学习。Y延续此前CSV用的核心结果，没有新增Y窗口。`correction_x = raw_x - result.x`，夜窗外有限X的补偿为0，无效值仍为NaN。

`result.x_source`：`NoOutput`表示不发布，`RawObservation`表示原始X，`NightCorrection`表示选择了夜间链路；最后一种不保证每个点已成功校正，仍需结合`output_ready`及核心诊断。`info_x/info_y`保留内部诊断，可能与发布来源不同。

07点是原始/修正坐标的分段边界。保留`x_source`，不要将切换前后的坐标差直接算作同一连续段位移。这里没有新增硬压幅，也不保证所有测点均小于1pixel；保持此前已审阅的算法行为与波形限制。

旧的全局 `ApplyModalSelfCal` 调用方式仍保留，并共用本版X路由。但它原有接口不返回`output_ready`，重复帧可能返回预填raw；`GetLastModalSelfCalInfo`在底本中是未填充信息的占位实现。本次不扩大改动去重写它们。需要精确发布判断和诊断时使用上面的对象接口。新增结果字段后必须用同一版cpp/h重新编译客户端，不承诺旧二进制ABI兼容。
