# 23—07夜间修正、07后原始观测的输出适配

用户已确认07:00后只看原始X，因此无需把退出恢复斜坡继续作为修后曲线展示。这里提供独立头文件 `NightWindowOutput.h`：**每帧仍先调用原核心；仅发布23:00（含）—次日07:00（不含）的Astra X，其他时间发布同帧原始X；Y保持原核心输出。** 没有修改此前算法源码、状态结构或配置，也没有增加运维参数。

新算法仍可使用已有Astra＋07:00渐退核心。其内部正常维护状态；07之后选择器发布原始值，内部退出估计不是对外的修后观测。不能把外部选择器放在核心调用前，按时段跳过核心。

## 接入方法

将本目录加入头文件路径，同时使用已审核的 `ModalSelfCal.h/.cpp`。已有引擎初始化、历史回放、状态导入导出流程照常。业务每帧调用位置可替换为：

```cpp
#include "NightWindowOutput.h"

astra_publication::NightWindowOutput frame;
std::string error;
if (!astra_publication::ProcessForPublication(
        engine, timestamp_ms, raw_x, raw_y, &frame, &error)) {
    // 使用原有错误处理；不发布该次结果。
    return;
}
if (!frame.output_ready) return; // 重复帧、历史回放等情况不发布。

// 对外X：frame.x
// 对外Y：frame.y()，与原核心Y完全相同。
// 对外实际补偿：frame.correction_x、frame.correction_y()
// 对外X来源：frame.x_source（RawObservation / NightCorrection）
// 内部诊断：frame.core.info_x / info_y；内部估计：frame.core.x / y。
```

如果现有代码必须保留自己的 `engine.Process()` 调用，也可先将同帧结果放入 `frame.core`，再调用 `SelectPublishedX(raw_x, &frame, &error)`。两种接法选一种，不能重复调用核心。这个选择器不单独读数据库，不转换scale，也不重算X/Y。

## 时间和精确边界

选择器读取该帧核心 `info_x.night_hour`，直接复用核心的时区换算，不使用操作系统本地时区。当前项目核心为UTC+8；夜内00点记作24，07点记作31，因此判定是 `[23,31)`。

|采集时间（按核心配置的本地时间）|发布X|核心仍处理|
|---|---|---|
|22:00—22:59:59.999|原始X|是；这段仍收集22—23基线|
|23:00:00.000|核心X|是；进入坡段的第一帧也属于夜间输出|
|00:00—06:59:59.999|核心X|是|
|07:00:00.000及以后|原始X|是；不把退出渐退值发布为观测|

23—07只是发布窗口，不把历史学习改成23—07，也不阻断原22—02统计。窗口内选择核心X不等于这一帧一定完成模态修正；冷启动、缺少基准、降级等情况仍须查看核心原状态。禁用核心时仍保留其原始输出行为。

## 无效值、重复帧和重启

- 调用前继续将ROI无效、缺测点表示为NaN，不能把无效但落库有数值的点直接当有效raw。适配器没有ROI字段可自行判断。任何原始X非有限值，发布X和补偿X都保持NaN；不填零、不插值、不因切到原始路由而提升有效性。
- 窗口内核心输出为NaN时，选择器保留该NaN，不自动用原始值补洞。窗口外有限raw逐值原样输出；补偿为0，原始无效点补偿仍为NaN。
- 重复或历史回放沿用核心的 `output_ready=false`，外部也不发布。处理成功不代表有可发布结果，应检查包装结果的 `output_ready`。
- 适配器无跨帧缓存，不需要新增快照或运维状态。重启依旧先恢复核心，随后用每帧核心时间选择输出。不能把离线选择器重启一致性等同于新验证了核心恢复；核心恢复证据仍来自此前测试。
- 只加输出适配器本身不改变核心配置指纹，不应因此清空已有历史。若同时升级核心源码或配置，依旧遵守原版本的状态兼容规则。

## 07点是观测段切换

07前修后X和07后raw X可能存在一个非零坐标差，这是本次明确的观测源切换。绘图应在 `x_source` 改变处断开曲线，并标注“夜间修正结束／原始观测开始”；不要连成连续物理运动。首帧、重启或跨过未观测时段也应按既有分段规则处理。

保存、送平差或报警的调用层应随数值记录 `x_source`，不应跨这个来源边界直接计算位移变化。07后的原始观测链按既有业务使用，不由适配器改变阈值或物理解释。

`frame.core.info_x`保留的是内部计算状态。例如07后核心仍可能处于RAMP，但对外X来源已经是RawObservation；对外展示应读取 `frame.x_source`，实际补偿用 `frame.correction_x`，不要把内部n_corrected作为对外修正状态。
