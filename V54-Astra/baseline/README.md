# Guangzhou Metro ModalSelfCal-V54 (方案 D: 生产级温和物理自校准版本)

## 一、方案 D 核心算法拆解与数学思路

针对现场 X 向在夜间（23:00–07:00）出现的恶性跳变与整机慢漂，方案 D 严格遵循**“拒绝数学假拟合、解耦物理扰动、分层逐步收敛”**的工程哲学，将现场噪声划分为三种完全不同物理尺度的扰动，并分层处理：

```text
原始提点 (mm)
  │
  ├── Y 向: 100% 透传原有 V51 生产链路 (无任何修改，与现场 V51 保持逐字节/逐值一致)
  │
  └── X 向:
        │
        ▼ 【第一层：X 向输入端 W=3 因果中值滤波】
        │   - 物理目标：消除现场相机光学成像中的单帧 ±1 pixel 提点高频抽搐（白噪声孤立点）。
        │   - 数学实现：纯因果 3 帧滑动内存，t 时刻取 [x(t-2), x(t-1), x(t)] 的中位数。
        │   - 物理保真：单帧阶跃 100% 稳态保留，斜坡与连续变化 0 偏差透传，零未来数据。
        │
        ▼ 【第二层：原版生产 V51 模态解算核心】
        │   - 物理目标：消除多测点间由隧道整体微变形与基准变动引起的低阶耦合形变。
        │   - 数学实现：
        │       1. 22:00–23:00 基线学习窗：逐点均值 b 锚定为当夜“真实位移物理零点”；
        │       2. 22:00–02:00 历史协方差矩阵学习：前 3 夜协方差合并特征分解，提取 K=3 空间模态 A；
        │       3. 逐帧最小二乘反解时间模态系数 v(t)，扣除模态分量 A*v 并基线再锚定 c̄；
        │
        ▼ 【第三层：X 向夜间温和物理增强 (仅在 23:00–07:00 施工期 gate>=1.0 生效)】
            │
            ├─ [S2: 55% 支架温漂弹性自校]
            │    - 物理目标：夜间隧道因通风与气温降低 1.2℃~3.0℃，导致相机悬臂铝合金/钢支架发生物理微温缩，
            │      表现为该设备视场内所有 Marker 同时向同一方向慢速蠕变。
            │    - 数学实现：
            │        1. 23:20 起记录前 30 帧基准 b_j = median(x_j)；
            │        2. 实时计算全视场有效点相对偏差的中位数 D(t) = median_j(x_j(t) - b_j)；
            │        3. 通过 15 帧滑动中值提取该设备共模慢漂趋势 D_slow(t)；
            │        4. 仅弹性扣除 55% 支架温缩共模项：x_j = x_j - 0.55 * D_slow(t)。
            │        （单点自身的相对物理位移与形变 100% 保留，绝不向零点强拉）。
            │
            └─ [S1: 1.5 分钟因果弱阻尼 (tau=1.5min, alpha≈0.486)]
                 - 物理目标：平抑施工期间机械施工、活塞风等造成的 1 分钟级短时微震动。
                 - 数学实现：一阶递归惯性滤波 s(t) = s(t-1) + alpha * (x(t) - s(t-1))。
                 - 异常旁路：遇到断采 (>3min) 或时间戳乱序自动重置，保留真实结构突变。

        ▼ 【第四层：白天时段 (07:00–23:00)】
            - gate == 0 时 100% 透明透传，不介入任何夜间温漂修正与阻尼。
```

## 二、运行机制：长周期（不停机 1 个月以上）与状态包设计

针对软件同事最关心的**“长时间运行是否会内存泄漏/漂移”**以及**“异常重启是否只依赖易失缓存”**的两个关键工程问题，V54 做了专门加固设计：

### 1. 长周期（不停机 1 个月以上）运行安全性
- **内存占用严格恒定（$O(1)$ 复杂度）**：
  - 所有测点状态数组、中值窗口、阻尼变量均在 `Init` 时预分配（按测点数，每个设备仅几十 KB 内存）。
  - 处理过程中**没有任何 `new` / `malloc` / 容器无限制增长操作**，运行 1 个月或 1 年内存恒定不变，绝对零内存泄漏。
- **24 小时生命周期自重置机制**：
  - 每天早晨 07:00 施工结束，`gate` 归零，系统自动切换为白天透传模式；
  - 每天夜间 22:00 基线学习窗开启，23:00 施工窗开启，系统会以当夜最新的温度和实际提点自适应建基线。
  - **绝不存在跨天或跨月累计的“数值漂移”**。

### 2. 重启与状态包（State Snapshot）机制
- **之前放状态包的做法完全保留，且已经支持方案 D**：
  - 我们将方案 D 的全部运行时状态（温漂基准 `baseline_reference`、共模滑动窗口 `rolling_drift`、阻尼状态 `s`、W=3 缓存）**无缝打包序列化进现有状态包（`ExportState` / `ImportState`）**。
- **两种启动场景的处理**：
  1. **热重启（推荐上线方式，有状态包）**：
     - 如果程序在夜间（例如凌晨 03:30 施工高峰期）崩溃重启，调用 `ImportState` 恢复状态包；
     - **毫秒级 100% 恢复当夜的温漂基准和阻尼状态**，下一帧输出与崩溃前**逐比特严格连续**，不需要重新积累 30 帧基准，零延迟、零跳变！
  2. **冷启动（容灾保底机制，无状态包）**：
     - 若现场首次部署、更迭设备或状态包文件损坏，传入 `allow_new_stream = true`（V54 默认值）；
     - 算法会自主启动并在当夜在线完成基线自学，保证系统永远不会因为“找不到状态包”而卡死或拒绝服务。

## 三、文件清单与编译说明

| 文件名 | 说明 |
| :--- | :--- |
| `ModalSelfCal.h` | 统一头文件，包含配置结构体 `ModalSelfCalConfig`、类接口 `ModalSelfCalState` 及全局函数接口 |
| `ModalSelfCal.cpp` | 完整自包含实现（~74 KB），内置模态核心、W=3、S2、S1 以及状态包序列化/反序列化逻辑 |
| `test_v54.cpp` | 包含冷启动、白天透传、夜间时序、全局 API、状态快照热重启 5 大测试用例 |

### 编译命令
纯 C++17 标准库，无任何第三方库依赖：
- **MSVC (Visual Studio 2019/2022)**:
  ```bash
  cl /std:c++17 /O2 /utf-8 /EHsc ModalSelfCal.cpp your_main.cpp /Fe:app.exe
  ```
- **GCC / Clang**:
  ```bash
  g++ -std=c++17 -O2 ModalSelfCal.cpp your_main.cpp -o app
  ```
