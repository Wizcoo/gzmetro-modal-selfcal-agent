## 1. 用户真正要解决的问题

项目是广州地铁视觉位移监测中的夜间坐标扰动修复。数据库原始 `x/y` 是 pixel；`calX/calY` 是修正后的像素坐标，后续另有平差/解算得到 `x0/y0` 等物理量。用户反馈约 1 pixel 的误差可能被解算放大到数毫米，现场预警约 3 mm；这只是用户的业务背景，不能当作已经标定的通用 `1 pixel = 4 mm` 换算。

最高优先级是保留可用于判断真实运动的波形、峰谷出现时间与相对观测关系。在扰动明显的夜间可以加强修复；平稳夜只做小修。不能靠压平、延迟或抹掉真实位移换取漂亮的范围通过率。用户希望规则有物理解释、鲁棒、少参数，不希望维护人员逐设备/逐点手调。

当前最重要的未解决问题是：**历史空间关系在今天失效后，如何阻止继续过量补偿，同时保留真实运动与时间连续性。** 典型担忧是前三夜波动大，第四夜变安静；实际失败还包括某点很静而其他点变化、旧关系把局部变化投影到别的点、有效点集合变化和基准/缓存跨界。

## 2. 已确认的业务约定

- 夜号按开始日期表示，例如 `2026-11-12 夜` 指 11/12 23:00（含）至 11/13 07:00（不含）。时区 UTC+8，输入时间戳 Unix 毫秒。不能把本地夜号与 UTC 日期混用。
- 主评价/发布窗为 **[23:00, 次日07:00)**。07点后用户只看原始X，夜间修正段可以结束；07点来源切换不能当作同一连续修正段的真实位移。22–23基准帧仍必须输入，不能只调用夜窗内数据。
- 普通点修后X整夜 `max−min` 尽量≤1 pixel，最多2 pixel。J固定基准点目标≤1 pixel。1/2 pixel指**修后X的整夜波动范围**，不是单帧补偿量上限。
- **J（YJ/ZJ）是默认不动的基准点；XJ（YXJ/ZXJ）是相机旁的普通测点，不能假设不动。** 后续用户允许XJ在与本设备整体同趋势时保留波动；XJ绝对范围、XJ与目标/J的相对差必须分开报告，不能机械按XJ>1判业务失败，也不能因相关性高就宣布平差会完全抵消。
- 目标为左右线各6台，共12台设备，完整10夜回测约95%通过是理想值，可接受诚实报告实际达到多少、哪些失败及为什么。物理保真优先于这个数字。缺夜/低覆盖单列，不补造、不换夜、不从分母中悄悄删除。
- `max_frame_dev=0` 已关闭单帧绝对偏差初筛，它是求解点资格规则，**不是**输出限幅；不能改回8并称作用户的安全上限。

## 4. 算法当前如何运行

1. X先经过因果W3中值预处理，之后是历史模态补偿，再经过S2共同慢漂修正与S1弱阻尼，最后按23–07选择发布X。Y保留当前基线核心行为，X研究不能顺带改变Y。
2. 本夜22–23建立基准；有历史时23点冻结当前模型。默认用最近3个合格历史夜，每夜学习统计为22–次02，**不是**3个完整23–07夜。已有历史模型时，本夜02点后数据不会重新拟合本夜空间关系；历史正常滚动供后续夜使用。
3. 历史储存跨点统计/空间载荷；每帧模态系数由**当前有效学习点相对本夜基准的变化**重新求解。它不是按时刻重播历史扰动波形。当前全点从基准起严格恒定时，不应因为过去强波动就凭空产生模态补偿。
4. 现有Astra增强是X专用的跨夜回归能量约束：有效但不参与学习、且非fit_only的回归点按 `gain=clip(2*min(q_n),0,1)` 收缩历史不可靠载荷。**学习点和fit_only点不受这条新增约束覆盖。** 历史代理能量下降不等于当前绝对误差小、当前不反向或真实运动被保留。
5. YJ/ZJ按fit_only处理，不参与模态学习/当帧SolveV，但仍可被回归补偿。XJ属于普通测点身份，可能因spread/guard变成非学习回归点。实时残差剔除只覆盖相应求解点，不能当全体输出的保护网。
6. `gate=0`、`CORRECTING`、`n_history=3`、`NightCorrection`等都不能单独证明输出有效或物理正确；W3/缓存/发布选择与模态状态需分别看。
